## 2024-05-18 - SQLite `TEMP B-TREE` in Pagination Queries
**Learning:** In SQLite, pagination queries (e.g., using `ORDER BY created_at DESC, id DESC LIMIT 20`) can cause a severe performance bottleneck if the indexes do not exactly match the `ORDER BY` clause. When there is an index mismatch, SQLite evaluates the `WHERE` clause first and then loads all matching rows into memory to sort them using a `TEMP B-TREE` before applying the `LIMIT`. This turns an O(K) lookup into an O(N log K) operation. The `jobs_listing` and `candidates_listing` indexes used `updated_at DESC` instead of `created_at DESC` which triggered this issue for `jobs_search` and `candidates_search` respectively.
**Action:** Always verify with `EXPLAIN QUERY PLAN` that search/pagination queries map perfectly to an index, completely avoiding `TEMP B-TREE` for the `ORDER BY`. Make sure the `ORDER BY` columns are covered exactly in the same direction in the composite index.
